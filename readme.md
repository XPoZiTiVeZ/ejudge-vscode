# Ejudge Wrapper — расширение VS Code

Дерево контестов слева (URL + логин/пароль + опциональный SOCKS5-прокси), встроенная вкладка ejudge
справа с автологином, back/forward/reload в панели редактора и своей кнопкой выбора файла вместо
системного диалога.

## Структура проекта

```
ejudge-vscode/
├── package.json
├── tsconfig.json
├── src/
│   ├── extension.ts
│   ├── contestsProvider.ts
│   ├── contestSettingsPanel.ts   (форма настроек контеста — отдельная вкладка)
│   ├── contestPanel.ts
│   ├── proxyServer.ts
│   └── clientScript.ts
└── resources/
    ├── icon.svg   (значок в Activity Bar, 24x24)
    └── icon.png   (значок расширения в разделе Extensions, 128x128 PNG)
```

`contestSettingsPanel.ts` в этом наборе не прикладываю — это ваш собственный файл (форма
добавления/редактирования контеста с полями SOCKS5-прокси), `contestsProvider.ts` подстроен под
его интерфейс: `ContestFormData`, `upsertContest()`, `getProxyPassword()`.

## Установка и запуск

```bash
npm install
npm run compile
```

`F5` — Extension Development Host, или сборка `.vsix`:

```bash
npx @vscode/vsce package
code --uninstall-extension local.ejudge-vscode
code --install-extension ejudge-vscode-<версия>.vsix
```

Требуется **Node.js 20+** для `@vscode/vsce@3.x` (используйте `nvm install 20`, если системный
Node старее). После переустановки закрывайте и заново открывайте вкладку контеста — reload внутри
уже открытой вкладки не подхватывает изменения кода расширения.

## Как это работает

### Прокси и обход CORS

Локальный HTTP-прокси (`proxyServer.ts`) поднимается на `127.0.0.1:<случайный порт>` и:

- проксирует запросы к ejudge, храня cookie-сессию отдельно на каждый контест (хотя многие версии
  ejudge держат сессию через `SID` в URL, а не через cookie — прокси прозрачно пробрасывает и то,
  и другое);
- при ответе `text/html` переписывает ссылки в **чисто относительные пути** (без ведущего `/`) —
  это критично для работы через любую обёртку типа code-server, у которой есть свой собственный
  `/proxy/<port>/`-механизм: абсолютные пути ловили бы её, а не наш, и ловили ошибку `400 Invalid
  port`;
- встраивает свой `<script>` прямо в HTML, благодаря чему скрипт получает полный DOM-доступ (в
  отличие от обычного `<iframe src="https://ejudge...">`, где браузер блокирует это как cross-origin).

### Панель контеста и доступ через vscode server

`contestPanel.ts` — `WebviewPanel` с единственным `<iframe>` на прокси. Адрес получаем через
`vscode.env.asExternalUri(...)`, а не `http://127.0.0.1:port` напрямую — критично для Remote-SSH /
Codespaces / code-server, где Node-процесс расширения и клиентский браузер физически разделены и
нужен туннель порта.

**Важно про CSP**: в `<head>` вебвью обязателен `style-src 'unsafe-inline'` в
Content-Security-Policy — без него собственный `<style>` вебвью не применяется, и iframe
откатывается к дефолтному браузерному размеру (~300×150px), выглядя как "окно в окне".

### Back / Forward / Reload

Кнопки в реальной editor title bar (не внутри контента вебвью!) — контрибуция `editor/title` с
условием `"when": "activeWebviewPanelId == 'ejudgeContest'"` (появился в VS Code 1.71). Команды в
расширении шлют `postMessage` в вебвью, где маленький скрипт вызывает
`iframe.contentWindow.history.back()/forward()` — эти два метода спецификация разрешает вызывать
даже кросс-origin (в отличие от чтения `history.length` или `location`).

### Автологин

`clientScript.ts` ищет `input[name="login"]`/`input[name="password"]` (плюс общий fallback), жмёт
кнопку `action_2` если есть, иначе любую submit-кнопку в форме. Раскрытая форма логина **никогда не
показывается пользователю** — вместо неё оверлей "Вход в систему..." или явная ошибка после 3
попыток. Счётчик попыток сбрасывается при успешном входе и при каждом новом открытии вкладки —
иначе контест, ранее исчерпавший попытки, сразу показывал бы ошибку при следующем открытии без
единой новой попытки.

### Подгонка ширины под вкладку

Классическая тема ejudge не адаптивна (фиксированная колоночная вёрстка). Скрипт:

1. снимает `max-width`/`width` ограничения с известных контейнеров ejudge (`#main-cont`,
   `#l12-col`, `#l12` и т.п.);
2. оборачивает всё содержимое `<body>` в один контейнер и масштабирует его через
   `transform: scale()` (не `zoom` — он вызывал баги с округлением и с корректностью измерения
   `scrollWidth` при `overflow-x: hidden`);
3. пересчитывает масштаб по `resize`/`MutationObserver` и — на случай, если эти события не
   долетают из-за вложенности iframe в VS Code webview — дополнительно раз в 500мс проверяет
   реальную ширину вкладки.

Свои оверлеи (вход, выбор файла) выносятся на уровень `<html>`, минуя обёртку, чтобы не сжиматься
вместе со страницей.

### Свой выбор файла

Перехватывает клик по `input[type=file]` (включая программный клик через кастомную кнопку самого
ejudge) и показывает оверлей с тремя разделами: **открытые файлы** (`vscode.window.tabGroups`),
**рабочая область** (`vscode.workspace.findFiles`), **домашняя папка `~`**. Выбранный файл читается
через `/ejudge-api/read-file`, оборачивается в `File`/`DataTransfer` и подставляется в
`input.files` — форма отправляет его как обычно, POST (включая `multipart/form-data`) идёт через
прокси без парсинга, байты передаются насквозь.

### SOCKS5-прокси на контест

Если в настройках контеста указан SOCKS5-прокси (host/port/username/password), все запросы к этому
контесту идут через него (`socks-proxy-agent`, схема `socks5h://` — DNS резолвится на стороне
прокси). Актуально, если сеть VM не может достучаться до конкретного хоста напрямую (блокировка
провайдера, гео-ограничения и т.п.), но прокси с доступом туда есть.

### Логи

Output Channel **"Ejudge"** (`View → Output`, выбрать в дропдауне): запуск прокси, каждый
проксируемый запрос с таймингами по фазам (DNS lookup / TCP connect / TLS handshake / получение
ответа — так сразу видно, на каком этапе зависает), ошибки апстрима, и сообщения из самого
инжектированного скрипта (`/ejudge-api/log`), включая попытки автологина и их результат.

## Известные ограничения

- Селекторы логина/сабмита эвристические с fallback'ами; для нестандартных тем — "Ejudge: Edit
  selectors" в контекстном меню контеста.
- JS-редиректы внутри страницы (`window.location = ...`) не переписываются — только атрибуты
  `href/src/action/formaction` и заголовок `Location`.
- Внешние домены (не совпадающие с origin контеста) не проксируются намеренно.
- Старые серверы, требующие TLS legacy renegotiation (OpenSSL 1.0.x эпохи), поддерживаются через
  `crypto.constants.SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION` — это регресс OpenSSL 3.0/Node 17+,
  без явного флага соединение просто зависает без ошибки.
- Прямые TCP-таймауты (сеть VM физически не достаёт до хоста) не лечатся кодом расширения — только
  SOCKS5-прокси с реальной связностью до нужного хоста.
